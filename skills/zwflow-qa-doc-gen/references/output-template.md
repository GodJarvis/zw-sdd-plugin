# 接口测试用例输出模板


本文档定义最终输出的 markdown 用例文档结构。所有输出必须严格遵循该模板：极简元信息 + 模块标题 + GIVEN/WHEN/THEN 缩进式用例，**全文不允许出现横排用例表格**。

> 风格参考：团队既有模板 `qa-testcase-template.md`。本模板与之对齐。

## 完整结构

````markdown
# {接口/项目名称} 测试用例

> **编写人**：{留空待填}
> **日期**：{YYYY-MM-DD，自动填今天}
> **关联需求**：{接口路径或文档链接，自动填}

> ⚠️ 本文档中的 token / cookie / csrf 已脱敏为 `<token>` / `<csrf>` / `<session>` 占位符。实际执行时请替换为有效值。

---

## 模块：{接口名称 = summary}

### TC-000: 设计假设说明

- **说明**:
  - 本用例集基于以下假设设计，如与实际不符请反馈：
    - {假设 1}
    - {假设 2（如有）}

### TC-001: {主题} - 正常流程

- **前置条件(GIVEN)**:
  - {登录态、数据库初始数据、依赖的外部状态}
- **操作(WHEN)**:
  - {METHOD} {path}
  - Body: `{...}`
- **预期结果(THEN)**:
  - HTTP 200（或具体 status_code 值）
  - 响应字段断言（关键字段名 + 类型 / 具体值）
  - 数据库 / 副作用断言（如适用）

### TC-002: {主题} - {场景}

- ...

### TC-101: {主题} - 参数校验

- ...

### TC-201: {主题} - 边界场景

- ...

### TC-301: {主题} - 业务规则

- ...

### TC-401: {主题} - 响应校验

- ...

---

## 模块：{第二个接口名称}（多接口场景才有）

### TC-001: ...

（同结构。注意：每个模块**重新**从 TC-001 起编号；跨模块引用用 `模块A.TC-105` 形式）
````

## 关键规则

1. **全文无横排用例表格**：禁止把整条用例（GIVEN+WHEN+THEN）压缩为表格行。但 WHEN 段内的**数据驱动变体表**和**决策表矩阵**允许使用 markdown 表格（它们是参数化描述，不是用例本身）。
2. **编号 TC-NNN 按维度前缀分配**：
   - TC-0xx → 正常场景（维度 1）
   - TC-1xx → 参数校验（维度 2）
   - TC-2xx → 边界场景（维度 3）
   - TC-3xx → 业务规则（维度 4）
   - TC-4xx → 响应校验（维度 5）

   编号在每个维度内从 1 开始；每个**模块**独立编号空间，模块间从 TC-001 重新起。
3. **不使用 `### 3.1` ~ `### 3.5` 维度小标题分组**：所有用例**平铺**在 `## 模块` 下，按 TC-NNN 顺序排列即可。
4. **用例标题格式**：`### TC-NNN: {主题} - {场景描述}`，例如：
   - `### TC-001: 合法参数主链路 - 正常流程`
   - `### TC-103: zm_id 空字符串 - 参数校验`
   - `### TC-208: page_size 上界离点 - 边界场景`
5. **设计字段（优先级 / 测试方法）不出现在最终输出**：仅在 `coverage-dimensions.md` 的骨架表中作为设计指引保留；最终用例只含 GIVEN/WHEN/THEN 三段。
6. **TC-000 始终保留**：每个模块**必有** `### TC-000: 设计假设说明`，即使只有 1 条假设也保留（统一格式，便于团队快速定位假设）。仅含 `**说明**:` 一节，列出全部假设。
7. **预期结果(THEN) 必须可断言**：
   - 响应断言（HTTP status / 关键字段名+值）必有
   - 数据库 / 副作用断言（如适用）必有
   - 禁止"返回成功"等无法断言的描述（与 `qa-testcase-template.md` 书写规范一致）
8. **GIVEN / THEN 每条独立一行**：详见 `writing-rules.md` 规则 2（一行一断言，禁用 `；` / `、` 串接，状态码/字段/副作用各独占一行）。

## 公共请求约定

当所有用例共享同一组 URL / Method / Headers / 鉴权前置时，在文档顶部增加一节：

```markdown
## 公共请求约定

> 所有 TC 默认使用以下约定；WHEN 段仅描述差异部分（Body 或被替换的 Header）。

- **URL**: ...
- **Method**: POST
- **Headers**:
  - `Content-Type: application/json`
  - `Cookie: ...`
- **鉴权前置**："已登录"= 上述 Cookie + Header 均有效且配对
```

**Auth-Id 鉴权变体**（内部调用场景）：

```markdown
## 公共请求约定

> 所有 TC 默认使用以下约定；WHEN 段仅描述差异部分（Body 或被替换的 Header）。

- **URL**: ...
- **Method**: POST
- **Headers**:
  - `Content-Type: application/json`
  - `Auth-Id: <掌权用户UID>`
- **鉴权前置**："已登录"= 上述 Auth-Id 对应掌权真实用户且有所需路由权限
```

效果：
- 每条用例的 GIVEN 只写"已登录"或差异前置，不再重复 Auth-Id / Header 全文
- 每条用例的 WHEN 只写 Body 或要修改的单个 Header，不再重复 URL / Method
- TC-301~304（鉴权类）显式覆盖公共约定中的某一项即可

## 公共业务节

多接口汇总文档（N≥2 接口合并为单文件）在「公共请求约定」之后,根据冗余识别（见 `coverage-dimensions.md` 跨模块对称冗余识别节）可能再抽 0~2 个公共业务节,顺序固定:

```markdown
## 公共请求约定               (必有)
## 公共失败响应契约           (推荐)
## 公共字段约束-<业务>        (≥2 写入接口共享 ≥3 条同质 TC 时)
```

### 公共失败响应契约（推荐）

固化全文「业务校验失败的响应形态」,避免 THEN 中出现"HTTP 200 或 400(取其一)"等不可执行描述:

```markdown
## 公共失败响应契约

> 本接口集所有错误响应统一遵循:
>
> - **HTTP 状态码**: 200(即便业务校验失败也返回 200,不使用 4xx 区分参数错与业务错)
> - **业务状态码**: `status_code != 1` 表示失败
> - **错误信息**: `msg` 字段返回错误描述
>
> 全文 THEN 不再写 "HTTP 200 或 400(取其一)"/"或服务端容错处理" 等择一描述,统一断言 `HTTP 200 + status_code != 1`。
```

判断项目风格的规则详见 `coverage-dimensions.md`「失败响应契约判断信号」节。**核心原则：固化一种风格，THEN 中不写"或"**。

### 公共字段约束-<业务>（条件抽取）

多接口共享同一组字段约束时抽取,典型业务名: `公共字段约束-管理客服`、`公共字段约束-订单创建` 等。编号 `公共-TC-CXX`(C=C01/C02..., 表示 Common,与列表 1xx 区分)。

**业务名命名规则**:
- 格式: `公共字段约束-<业务实体>`
- 业务实体推断顺序: 接口共同的资源名(如 add/edit 客服 → "管理客服") → 公共字段集主题(如 name+message → "消息字段") → 批量主题(兜底)
- 允许中文短语,长度 ≤ 8 个汉字
- 不要超过 1 层,避免 `公共字段约束-管理-客服-账号` 这种过细命名

```markdown
## 公共字段约束-管理客服

> 适用于模块 7 新增客服 / 模块 8 编辑客服。

### 公共-TC-C01: name 长度边界(数据驱动)
### 公共-TC-C02: 外键 ID 数值边界(0 / -1)
### 公共-TC-C03: 决策表(字段 X × 字段 Y 组合)
### 公共-TC-C04: 共有字段类型错配(数据驱动)
```

### 抽取阈值与反模式

详见 `coverage-dimensions.md`「跨模块对称冗余识别」节的阈值规则和反模式说明。

## 数据驱动用例写法

当多条用例 THEN 完全一致、仅 WHEN 不同时，合并为 1 条数据驱动用例。

**合并阈值与同质判定标准**详见 `writing-rules.md` 规则 4。

**输出格式示例**：

```markdown
### TC-103: 字段类型错配（多字段数据驱动）

- **前置条件(GIVEN)**:
  - 已登录
- **操作(WHEN)**:
  - 对下列每组 Body 各发送一次（数据驱动）：
    - `{"page":"one","page_size":20}` —— page 送字符串
    - `{"page":1,"page_size":"twenty"}` —— page_size 送字符串
    - `{"page":1,"page_size":20,"zm_id":123456}` —— zm_id 送整数
- **预期结果(THEN)**:
  - 每组请求均 HTTP 400
  - `msg` 含 "type" / "类型" 或指明出错字段名
```

## 文件落盘与元信息

- **文件名固定**: `qa-doc.md`
- **目录固定**: `openspec/changes/<change_name>/`（与 yapi.md 同级）
- **覆盖判定**: 写入前若 `qa-doc.md` 已存在，**必须向用户展示选项并等待明确选择**——具体选项见 SKILL.md 步骤 6
- **会话回复**：仅给文件链接 + 用例数量分维度摘要表 + 自检结果；不重复粘贴正文

**元信息默认值**：

| 字段 | 默认值 / Fallback 链 |
|---|---|
| 接口/项目名称 | `proposal.md` H1 标题 → 单接口取 `summary` → 多接口取首接口 path 有意义段 → 兜底 `change_name` |
| 编写人 | 留空（用户自填）|
| 日期 | 自动填今天 YYYY-MM-DD |
| 关联需求 | `./yapi.md`（相对路径,便于点击）|

## 多接口输出格式

每个接口独立成一个 `## 模块 N: xxx` 章节。**每个模块各自从 TC-001 起编号**（独立编号空间），跨模块引用用 `模块A.TC-105` 形式。

**多接口汇总文档结构**：

````markdown
# {批量主题} 接口测试用例汇总

> **编写人**:
> **日期**: YYYY-MM-DD
> **关联需求**: {来源文档名} ({N} 个接口批量生成)

> ⚠️ token / cookie / csrf 已脱敏。

---

## 公共请求约定

> 所有接口默认使用以下请求头与鉴权前置；各模块仅在路径/Body 上有差异。

- **Method**: 全部为 POST（或按实际）
- **Headers**: ...（共有 Header 一次性写在这里）
- **鉴权前置**: ...
- **Base URL**: `http://localhost`（各模块仅 path 不同）

---

## 模块索引

| # | 接口名 | 路径 | 用例数 |
|---|---|---|---|
| 1 | ... | `POST /xxx` | N |
| ... | | | |
| | | **合计** | **N** |

---

## 模块 1: {接口名}

> **路径**: `POST /xxx`
> **本次变更**:（如有）
> - ...

### TC-001: ...
### TC-101: ...

---

## 模块 2: {接口名}

> **路径**: `POST /yyy`

### TC-001: ...   <- 此处重新从 001 起
### TC-101: ...
````

**关键约束**：
1. 公共 Headers / Cookie / 鉴权约定**抽到顶部全局**「公共请求约定」节，各模块标题下只列「路径 + 本次变更」差异
2. 各模块标题统一为 `## 模块 N: <summary>`，TC 标题统一为 `### TC-NNN: <主题> - <场景>`（冒号分隔，禁用 ` 主题 — 场景` 这类破折号格式）
3. 顶部「模块索引」表必填，列出每模块用例数 + 合计
4. 不要在汇总文档中保留每个模块各自的「公共请求约定」副本

## 集成场景章节（TC-5xx，多接口时在所有模块之后）

当满足维度 6 适用条件时（≥2 接口 + 有跨接口信号源），在所有 `## 模块 N` 之后新增：

````markdown
---

## 集成场景

> 以下用例验证跨接口的业务流程联动，需按 Step 顺序依次执行。
> 数据来源：specs scenario / prd 业务流程 / design 状态机。

### TC-501: <流程名> - 正向主链路(prd)

- **前置条件(GIVEN)**:
  - 已登录
  - {依赖数据}
- **操作(WHEN)**:
  - Step 1: POST /xxx → response.data.id 记为 `$id`
  - Step 2: POST /yyy {"id": "$id"}
  - Step 3: GET /zzz?id=$id → 验证最终状态
- **预期结果(THEN)**:
  - Step 1: status_code=1, 返回 id
  - Step 2: status_code=1, 状态变为 processing
  - Step 3: status=completed, 结果字段非空

### TC-502: <状态机名> - 全链路遍历(状态机)
...
````

**集成场景编号规则**：
- TC-5xx 在文档级独立编号，从 501 起
- 不属于任何模块，放在「模块索引」之后独立计数
- 模块索引表中追加一行：`| 集成 | 集成场景 | — | N |`
- TC 标题末尾标注来源：`(prd)` / `(spec)` / `(状态机)`
- 上限 5 条

**Step 写法规范**：
- 每个 Step 标注接口路径（必须存在于 yapi.md）
- 跨 Step 数据传递用 `$变量名` 标记
- THEN 按 Step 分行断言，不混合

**跨 Step 变量命名规范**：

| 场景 | 命名格式 | 示例 |
|---|---|---|
| 简单链路（2 步 + 变量唯一） | `$<字段名>` | `$task_id` |
| 多步链路（≥3 步或同名字段出现多次） | `$<step序号>_<字段名>` | `$1_task_id`、`$3_record_id` |
| 同一 Step 返回多个字段 | `$<step序号>_<字段名>` | `$1_id`、`$1_token` |

规则：
- 变量在定义处（WHEN 的 `→` 右侧）首次出现，后续引用保持一致
- 当变量名全局唯一且无歧义时允许简写（省略 step 序号）
- 禁止同一 TC 内出现两个同名变量指代不同值

## 不要输出的内容

以下内容**禁止**出现在最终输出的用例文档里:

| 禁止 | 理由 |
|---|---|
| `**优先级**: PN` 字段 | 设计指引不出现在最终用例 |
| `**测试方法**: 等价类划分` 字段 | 同上 |
| 底部「## curl 调试示例」整段 | Body 在每条 TC 中已有,公共约定 + 路径足以拼 curl |
| THEN 中择一描述（「HTTP 200 或 400」/「按契约取其一」/「行为 A / B」） | 不可执行,必须固化(见公共失败响应契约) |
| TC 标题用破折号或空格分隔 | 必须统一为 `### TC-NNN: <主题> - <场景>` 冒号格式 |
| GIVEN/THEN 用 `；` `;` `、` 串接多条断言 | 必须一行一断言 |
| 每个模块各自重复的「公共请求约定」 | 多接口汇总文档统一抽顶部 |
| 单接口文档假装有多模块结构 | N=1 时直接 `## <接口名>` |
| 分页参数本身的用例 | 由前端 SDK 与网关统一保证 |
| GIVEN/THEN 中「或」/「按契约取其一」描述 | 必须固化为一个值或挪入 TC-000 假设 |

## 敏感数据脱敏

文档顶部紧跟元信息行固定加一行注释（即便输入未含真实敏感值，也建议加，便于团队约定）：

> ⚠️ 本文档中的 token / cookie / csrf 已脱敏为 `<token>` / `<csrf>` / `<session>` 占位符。实际执行时请替换为有效值。

脱敏映射：

- Authorization Bearer 值 → `<token>`
- Cookie 中 csrf-token 值 → `<csrf>`
- Cookie 中 session/jsessionid 值 → `<session>`
- 自定义 Header 中明显的 hash 值（长度 ≥ 32 且字符集 hex/base64）→ `<token>`
