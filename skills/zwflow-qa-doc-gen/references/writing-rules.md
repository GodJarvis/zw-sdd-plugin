# 测试用例书写硬规则（Writing Rules）

> 本文件是本 skill 的**强制约束**。生成用例时必须全部满足；落盘前按文末「自检清单」逐项核对。
> 这些规则源自团队多次回归反馈，违反任何一条都会被退回返工。

---

## 规则 1：用例必须写入文件，禁止粘贴会话

### 要求
- 最终用例文档必须使用当前宿主可用的文件写入能力输出为 `.md` 文件
- **不得**把完整用例正文粘贴在会话回复里
- 文件名格式：`<METHOD>_<path下划线化>_测试用例.md`（通用独立使用时）
- **openspec 工作流例外**：通过 `zwflow-qa-doc-gen` Skill 执行时文件名固定为 `qa-doc.md`，目录固定为 `openspec/changes/<change_name>/`（详见 `output-template.md`）
- 落盘目录：当前工作目录根（默认 cwd，openspec 工作流按上述例外）
- 会话回复仅包含：
  - 文件链接（markdown 相对路径，便于点击）
  - 用例数量分维度摘要表
  - 自检清单结果

### 为什么
长用例正文粘在终端难以阅读、复制、归档；落盘后才能纳入 git、共享、被自动化消费。

### 反例
❌ "下面是为你生成的 38 条测试用例：## 模块：xxx ### TC-001 ..."（正文铺满会话)

### 正例
✅ "已生成 → [POST_xxx_测试用例.md](POST_xxx_测试用例.md)（共 22 条,分布如下表...）"

## 规则 2：GIVEN / THEN 一行一断言,禁用分号顿号串接

### 要求
- `**前置条件(GIVEN)**` 与 `**预期结果(THEN)**` 下的每一条**必须独占一个 list item**
- **禁用** `；` / `;` / `、` 把多条并列断言串在同一行
- 状态码（`HTTP 200` / `status_code=1`）必须有独立一行
- 字段断言写「字段名 + 期望值/类型」形式
- 副作用断言（如「数据库无写入」）独立成行
- 「或 / 按契约取其一」等择一说明**禁止**出现 — 必须挪入 TC-000 假设或顶部公共失败响应契约节
- GIVEN 同此规则;鉴权前置可复用 `持有效鉴权（同 TC-001）` / `已登录（同公共约定）` 避免重复

### 为什么
一行多断言在 markdown 渲染后视觉密度高,执行人无法逐项勾选,也无法直接映射成自动化代码里的 N 条 assert。

### 正例
```markdown
- **预期结果(THEN)**:
  - HTTP 200
  - data.data=[]
  - total=3
  - page=99
```

### 反例
```markdown
- **预期结果(THEN)**:
  - HTTP 200；data.data=[]；total=3；page=99
```

### 字段写法对照
| ❌ 模糊 | ✅ 可断言 |
|---|---|
| 返回数组 | `data.data` 为 array |
| 返回成功 | `status_code=1` |
| 报错 | `status_code != 1` 且 `msg` 含 "userid" |

## 规则 3：批量改写先读取全貌再依次局部编辑

> ⚠️ **适用时机**：本规则仅在**修改已生成的 qa-doc.md** 时适用（增量更新 / 人工修订 / 用户要求局部调整）。首次全量生成直接写入整份文档，无需先读取再局部编辑。

### 要求
对已生成的用例 .md 做**小幅**批量修改时（< 10 处独立局部编辑；若 ≥ 30 处或跨模块重组请用规则 6 的整体重写策略）：

1. **先读取整个文件**掌握全貌（或通过文本搜索列出目标段落行号）
2. 在进度清单或回复中**列出每个 TC 待改的段落与具体位置**
3. 再依次局部编辑；每次局部编辑仅改一处
4. 每次精确编辑操作的源文本锚点**必须包含**：
   - 段落标签(如 `**预期结果(THEN)**:`)
   - 用例编号或紧邻上下文
   确保唯一定位,避免跨段匹配
5. 改完后通过文本搜索复核剩余符号（如剩余的 `；`），确认无漏改

### 为什么
不先列清单、直接连续执行多处局部编辑，极易把某条用例的 `**前置条件(GIVEN)**` 误改成 `**预期结果(THEN)**`，导致回滚。批量编辑同结构片段时，跨段错配是最常见事故。

## 规则 4：落盘前自检冗余,按 10 条模式合并/删除

### 要求
**写入之前**必须按下列 10 条模式扫一遍，合并或删除冗余用例：

| # | 冗余模式 | 处理 |
|---|---|---|
| 1 | 边界内点 ≡ 主链路:TC-2xx 的「上点/内点」Body 与 TC-001 相同 | 直接删,边界值只留**离点** |
| 2 | 同质类型错配 ≥ 3 条 | 合并为 1 条数据驱动用例(WHEN 列变体表) |
| 3 | TC-401 字段完整性 + TC-402 类型匹配 | 合为 1 条「响应结构契约(字段+类型)」 |
| 4 | TC-3xx 业务「查询无结果」 + TC-4xx「空集结构」 | 业务侧留「为什么」,响应侧只校验结构差异 |
| 5 | 空串与 null 拆两条且断言不一致 | TC-000 统一规则后合并为 1 条数据驱动 |
| 6 | 负数与 0 都做下界离点 | 仅保留 `min - 1`(通常 0),负数在描述里说明等价覆盖 |
| 7 | 每条 GIVEN 重写 Cookie/Header 全文 | 抽出 `## 公共请求约定`,GIVEN 写「已登录(同公共约定)」 |
| 8 | 每条 WHEN 重写 URL/Method/Headers | 同上,WHEN 只写差异 |
| 9 | TC-000 含「无写副作用」等通识假设 | 删;TC-001 的 THEN「数据库无写入」已覆盖 |
| 10 | THEN 出现「如/或/按契约」 | 固化一个值,或挪进 TC-000 假设,THEN 注明「待确认填入」 |

### 数据驱动合并阈值与同质判定
- **≥ 3 条同质用例**就合并为数据驱动
- 2 条仍可平铺

**同质判定标准**:
- WHEN 段(操作)+ THEN 段(预期)逐字相同 → **同质**,必须合并
- WHEN 段差异(变体值)但 THEN 共性 ≥ 70% → **近似同质**,可合并为数据驱动表
- 差异 > 30% → **异质**,保留各自用例

举例:
- 「name=空串」+「name=null」+「name=超长」3 条 THEN 都是 `status_code != 1 + msg 含 name` → 同质合并
- 「未登录」+「csrf 不匹配」+「token 过期」3 条 THEN 错误码不同(401 / 403 / 401) → 异质保留

### 为什么
用例不是越多越好。重复用例会稀释执行人对关键路径的注意力。某次通讯录列表初版 38 条,自检后压到 32 条,执行成本显著降低。

### 自检操作
- 文本搜索 `(THEN)\*\*:\n\s*-\s*HTTP 400` 这类高频 THEN，定位同质用例
- 文本搜索 `；` / `;`，确认无串接断言
- 抽公共约定时,URL / Method / Headers / 鉴权前置一次性写在 `## 模块` 标题前

## 规则 5:输出语言三层规则

### 要求
中英混合接口文档时:
- **用例标题、GIVEN/THEN 正文**:一律中文
- **字段名 / 枚举值 / Body 内容 / JSON 示例**:保留接口实际原文(不要翻译 `userId` 为 `用户ID`)
- **msg / 错误信息关键词搜索**:按接口实际语言推测(如英文接口的 msg 含 "required" 而非 "必填")

### 为什么
执行人需要按字面值与服务端响应比对;翻译字段名会让自动化脚本 assert 失效。

### 示例
✅ 正确(中文标题 + 原文字段):
```markdown
### TC-101: userId 必填字段缺失
- **预期结果(THEN)**:
  - HTTP 400
  - msg 含 "userId" 或 "required"
```

❌ 错误(把字段名翻译成中文):
```markdown
### TC-101: 用户ID必填字段缺失
- **预期结果(THEN)**:
  - msg 含 "用户ID 必填"
```

## 规则 6：何时局部编辑，何时整体重写

### 要求
按改动规模选择策略:
- **< 10 处独立修改** → 主流程逐处局部编辑（规则 3 适用）
- **10 ~ 30 处修改** → 判断是否跨多个章节；同一章节内连续修改可局部编辑，跨章节大改用整体重写
- **> 30 处修改 或 跨模块结构性重组** → 整体重写策略:
  1. 备份原文件为 `.bak`
  2. 交由独立执行单元一次性读取原文与 spec，再整体覆盖写入
  3. 通过文本搜索自检

### 为什么
逐处局部编辑的优势（局部可控）在 30+ 改动时会倒挂为劣势（跨段误匹配率指数上升）。本会话 168 → 124 重构若逐处编辑至少需要 30 次；整体重写只需一次写入，且备份可回滚。

### 反例
❌ 整个文档需要重排模块顺序时仍在局部编辑
✅ 整个文档需要重排时备份 + 整体重写

## 规则 7：WHEN/THEN 体禁止裸占位符

### 要求
- WHEN/THEN 体中**禁止**使用 `[具体任务ID]` / `<xxx>` / `xxx_id` 类裸占位符作为参数值或断言目标
- 需要运行时动态获取的值，MUST 在 THEN 中显式写「运行时动态获取 $task_id（Step N 响应 data.id）」
- 需要真实示例值的，MUST 填入真实示例值并注明「示例值，执行时替换为实际」

### 为什么
裸占位符导致 qa-test 生成测试代码时无法确定参数，要么 skip 要么硬编码错误值；且无法自动化校验。

### 正例
✅ `- Body: {"task_id":"$task_id"}` + THEN 注明「$task_id 运行时动态获取（Step 1 响应 data.id）」

### 反例
❌ `- Body: {"task_id":[具体任务ID]}`

## 规则 8：全称量词断言须显式写明无数据判定

### 要求
- THEN 含「每条记录」「所有记录」「返回记录均…」等全称量词的数据内容断言时，MUST 显式写明**无数据时的判定**
- 无数据判定三选一：
  - 「无数据时：status_code=1 + data.data=[] 视为通过（注明 vacuous）」
  - 「无数据时：markTestSkipped（无数据，无法验证）」
  - 「无数据时：失败（要求 staging 必须有数据）」
- 禁止 `if(!empty) 才断言` 式隐式空洞通过（无数据时 0 断言直接通过）

### 为什么
不写明无数据判定，qa-test 生成代码会用 `if (!empty($records))` 守卫，staging 无数据时 THEN 专属断言为 0，测试空洞通过但报告显示「全部通过」，误导性强。

### 正例
✅ THEN：
  - 每条记录的 call_status=1
  - 无数据时：markTestSkipped（无数据，无法验证）

### 反例
❌ THEN 只写「每条记录的 call_status=1」，未说明无数据时如何判定

## 落盘前自检清单(Checklist)

每次写入前逐项打勾，任一未通过则修订后再落盘：

- [ ] **规则 1**：用例正文已写入 `.md` 文件，会话回复仅含链接 + 摘要表
- [ ] **规则 1**:多接口(N≥2)已合并为 1 份 `<批量主题>_测试用例汇总.md`,未拆成多个独立文件(除非用户明确要求)
- [ ] **规则 2**:GIVEN/THEN 每条独占一行,全文搜索 `；` `;` 无命中
- [ ] **规则 2**:HTTP 状态码、status_code、msg 各有独立断言行
- [ ] **规则 4**:已扫描 10 条冗余模式,无遗留
- [ ] **规则 4**:同质用例 ≥ 3 已合并为数据驱动
- [ ] **规则 4**:已抽出 `## 公共请求约定`(多接口在文档顶部全局抽,各模块只标注路径与变更差异),GIVEN/WHEN 不重复写 URL/Header
- [ ] **规则 4 **:多接口汇总文档已扫描跨模块对称冗余 3 类(多端入口/列表参数/字段约束),按阈值合并或抽公共节
- [ ] **规则 4 **:THEN 无「HTTP 200 或 400(取其一)」/「按契约取其一」/「行为 A / 行为 B」择一描述,已固化或挪入「公共失败响应契约」节
- [ ] **内部接口跳过项**:未登录/csrf 不匹配/跨主体数据隔离/非管理员 这四类 TC-3xx 已删(除非用户要测安全边界)
- [ ] 编号 TC-NNN 在每个模块内按维度前缀(0xx/1xx/2xx/3xx/4xx)连续无跳号
- [ ] TC 标题统一 `### TC-NNN: <主题> - <场景>` 冒号格式,无 `### TC-NNN <主题> — <场景>` 破折号格式
- [ ] 顶部脱敏警告齐全(token/cookie/csrf 占位符)
- [ ] 每个维度至少 1 条 P0 用例(设计阶段判断,最终输出不显示优先级字段)
- [ ] 全文无 `**优先级**: PN` 字段(最终输出禁出现)
- [ ] 全文无 `**测试方法**: xxx` 字段(同上,设计指引不出现在最终用例)
- [ ] 全文无横排用例表格(WHEN 段内数据驱动变体表/决策表矩阵除外),使用 GIVEN/WHEN/THEN 三段缩进式
- [ ] 文档底部无「## curl 调试示例」段(Body 在 TC 中已有,公共约定 + 路径足以拼 curl,不要装饰性内容)
- [ ] **分页跳过**：全文搜索用例标题，应无 `page` / `pageSize` / `page_size` / `count` / `pageNo` / `limit` / `offset` 作为校验主体（除非用户明确要求）
- [ ] **TC-000 强制**:每个模块都有 `### TC-000: 设计假设说明` 节(始终保留,即使只有 1 条假设)
- [ ] **跨模块引用**：全文搜索 `模块[0-9]+\.TC-`，命中点都对应存在的模块编号，无悬挂引用
- [ ] **公共-TC 编号**:全文使用 `公共-TC-C0N`(C 前缀)而非 `公共-TC-A0N`(A 前缀);anchor 引用语法正确
- [ ] **输出语言**:用例标题/正文中文,字段名/枚举值保留原文(规则 5)
- [ ] **跨维度一致性**:TC-0xx 正常场景 THEN 的返回字段列表 ⊆ TC-401 响应校验的断言字段列表。TC-001 THEN 声明返回了字段 X 但 TC-401 未覆盖 → 补全 TC-401 或注明原因（如 X 仅在此场景返回）
- [ ] **规则 7**:WHEN/THEN 体无裸占位符（`[具体任务ID]`/`<xxx>`），动态值已注明获取路径
- [ ] **规则 8**:THEN 含全称量词断言（每条/所有记录）的用例已显式写明无数据时判定（vacuous/markTestSkipped/失败）
