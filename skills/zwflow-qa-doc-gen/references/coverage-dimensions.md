# 6 维度测试设计规则


> **重要**：本文档骨架表中保留 **优先级 / 测试方法** 两个字段作为**设计阶段**指引；但**最终输出的用例文档**只保留 GIVEN/WHEN/THEN 三段结构，不出现"优先级 / 测试方法"字段（详见 `output-template.md`）。
>
> **格式注意**：骨架中 GIVEN/THEN 使用分号简写便于快速阅读，**实际输出必须按 `writing-rules.md` 规则 2 拆为一行一断言**。骨架只传达"测什么"，不是输出格式参考。

## 避免冗余的设计原则

生成完用例后，**必须按 `writing-rules.md` 规则 4 的 10 条冗余模式自检并合并/删除**。

此外，**多接口汇总文档**还需扫描下节「跨模块对称冗余」。

## 跨模块对称冗余识别

多接口汇总文档（N≥2 接口合并为单文件）必须在落盘前扫这 2 类**跨模块**冗余 — 单接口文档不适用：

| 类型 | 识别信号 | 处理 | 阈值 |
|---|---|---|---|
| **A. 同业务多端入口接口** | 多个模块请求参数 + 响应结构**逐字相同**，仅 path 不同（如「企微端/sidebar端/微信在线客服端」三套礼包接口） | 合并为单一模块「<业务>-多端通用」，模块头部表格列出 N 个适用路径，TC 只写 1 套 | N ≥ 2 端 |
| **B. 同类接口共享字段约束** | 多个写入接口（add/edit/create/update）共享同一组字段的长度/类型/决策表（如 `name 长度` / `is_custom_welcome × message` 在 add 和 edit 都重复） | 顶部抽 `## 公共字段约束-<业务>` 节，列 `公共-TC-C01~C0N`(C=Common,与模块 TC-1xx 完全隔离),相关模块引用 | N ≥ 2 模块 共享 ≥ 3 条同质 TC |

**公共节命名约定**：
- 字段约束 → `## 公共字段约束-<业务>` + 编号 `公共-TC-C01~C0N`(C=Common)
- 失败响应 → `## 公共失败响应契约`（无 TC，1 段约定）

**引用语法**：模块内以 markdown anchor 引用 `> 参见 [公共字段约束-<业务>](#公共字段约束-<业务>) 公共-TC-C01~C0N 全部适用`。

**同质判定标准**：同 `writing-rules.md` 规则 4 的三级标准（逐字相同→同质 / 共性≥70%→近似 / 差异>30%→异质）。

**反模式 — 不要为合并而合并**：
- 模块名相同但响应字段集不同 → 不合(如 `促单案例列表` vs `智能质检列表`,都是列表但业务字段差异大)
- 共享 TC < 3 条（如 2 个接口只共享 1 条 name 长度校验）→ 不抽公共节,直接各自平铺
- 抽出公共节后剩余模块用例 < 3 条 → 不抽,直接平铺

## 失败响应契约判断信号

多接口汇总文档抽「## 公共失败响应契约」节时,需判断项目是哪种风格:

| 风格 | 判断信号 | 契约措辞 |
|---|---|---|
| **业务码全 200 风格** | 响应示例含 `status_code` / `code` / `errcode` 等业务码字段;成功响应 HTTP 状态全为 200 | "HTTP 200 + status_code != 1" |
| **RESTful 严格风格** | 响应示例无业务码字段;错误响应使用 4xx/5xx HTTP 状态码 | "参数错 = HTTP 400;业务错 = HTTP 409 或 422" |
| **混合风格** | 部分接口用业务码,部分用 HTTP 4xx | **不抽公共契约节**,各模块自陈;不固化 |

**判断流程**:
1. 取 input 中第一个有完整响应示例的接口
2. 看其错误响应:有 `status_code` / `code` / `errcode` 字段 + HTTP 200 → 全 200 风格
3. 没有业务码 + 错误用 4xx → RESTful 风格
4. 两种都有 → 混合,不固化

## 维度总览

| 维度 | ID 前缀 | 关键点 |
|---|---|---|
| 1. 正常场景 | TC-0xx | 合法参数、默认分页、不同业务取值 |
| 2. 参数校验 | TC-1xx | 必填缺失、类型错、空、null、超长、特殊字符 |
| 3. 边界场景 | TC-2xx | 数值上点/内点/离点；长度边界 |
| 4. 业务规则 | TC-3xx | 状态转换、前置依赖、幂等性、决策表、并发安全 |
| 5. 响应校验 | TC-4xx | 字段完整性、类型、排序 |
| 6. 集成场景 | TC-5xx | 跨接口链路、状态机全链路、流程中断一致性（≤5 条） |

> 维度编号在每个**模块**内独立、按维度前缀分配（TC-001、TC-101、TC-201、TC-301、TC-401）；跨模块从 TC-001 重新起。跨模块引用用 `模块A.TC-105` 形式。

## 归类决策表

| 测试场景 | 统一归到 | 理由 |
|---|---|---|
| Body 参数格式 / 类型 / 必填 / 长度 | **TC-1xx 参数校验** | 入参契约校验 |
| 数值 / 长度的上点 / 内点 / 离点 | **TC-2xx 边界场景** | 仅当字段定义有 min/max 时 |
| Header / Cookie 缺失（如 Content-Type、csrf Header） | **TC-3xx 业务规则**（内部接口默认跳过） | 按"调用接口的前置依赖"语义收口；内部接口由全局中间件统一处理 |
| 鉴权失败（未登录 / token 过期 / csrf 不匹配） | **TC-3xx 业务规则**（内部接口默认跳过） | 错误码 401/403；内部接口由全局中间件统一处理 |
| 数据隔离 / 越权访问 / 非管理员 | **TC-3xx 业务规则**（内部接口默认跳过） | 多租户隔离/RBAC 由基础设施保证 |
| 资源不存在 / 已软删 / 重名冲突 / 外键依赖 | **TC-3xx 业务规则** | 与接口语义强相关，必出 |
| 状态转换 / 幂等 / 前置依赖 / 字段决策表 | **TC-3xx 业务规则** | 原定位 |
| 仅针对成功响应的字段 / 类型 / 排序 / 脱敏 | **TC-4xx 响应校验** | 不重复维度 1 的请求场景 |

> 简记：**400 → TC-1xx，越界 → TC-2xx，业务/状态/幂等 → TC-3xx，成功响应结构 → TC-4xx**。
> **内部接口**（yapi / 公司内部 / `/admin` `/sidebar` `/internal` 路径）：401/403/数据隔离/非管理员**默认跳过**，详见维度 4 末尾「内部接口默认跳过的用例」。

## 维度 1：正常场景

- **ID 前缀**：TC-0xx
- **何时适用**：始终
- **设计思路**：等价类划分（取有效等价类代表数据）+ 场景法

### 典型用例骨架

#### TC-001: 合法参数主链路 - 正常流程
- **前置条件(GIVEN)**: 已登录用户持有效鉴权；业务数据准备就绪（如查询接口有 ≥1 条匹配记录）
- **操作(WHEN)**: {METHOD} {path}，Body 含所有必填 + 常用可选字段，取业务典型值
- **预期结果(THEN)**: HTTP 200；响应结构与契约一致（关键字段名 / 类型逐项断言）；副作用断言（如适用）：DB 表新增 / 状态字段更新
- **优先级**: P0
- **测试方法**: 等价类划分（有效类）

#### TC-002: 仅必填字段 - 省略所有可选
- **前置条件(GIVEN)**: 同 TC-001
- **操作(WHEN)**: 只传必填字段
- **预期结果(THEN)**: HTTP 200；可选字段返回默认值或省略
- **优先级**: P0
- **测试方法**: 等价类划分

#### TC-003: 仅必填参数查询 - 省略可选筛选条件
- **前置条件(GIVEN)**: 已登录；数据库有 ≥1 条匹配记录
- **操作(WHEN)**: 仅传必填参数，不传任何可选筛选/排序参数
- **预期结果(THEN)**: HTTP 200；返回列表非空；响应结构与契约一致
- **优先级**: P1
- **测试方法**: 默认值推测

#### TC-004: 业务枚举取值 A
- **前置条件(GIVEN)**: 数据库含 enum=A 的数据
- **操作(WHEN)**: enum 字段 = A
- **预期结果(THEN)**: 结果集合符合 A 语义
- **优先级**: P1
- **测试方法**: 等价类划分

### 避免冗余

- 不要在此维度生成边界值用例（属维度 3）
- 不要生成异常输入用例（属维度 2）

## 维度 2：参数校验

- **ID 前缀**：TC-1xx
- **何时适用**：始终（只要接口有任意参数）
- **设计思路**：等价类划分（无效等价类）+ 错误推测

### 典型用例骨架

#### TC-101: 必填字段缺失
- **前置条件(GIVEN)**: 已登录
- **操作(WHEN)**: Body 中移除某个必填字段
- **预期结果(THEN)**: HTTP 400 或 status_code=-1；error 指明字段名；无副作用
- **优先级**: P0
- **测试方法**: 等价类（无效类）

#### TC-102: 类型错配
- **前置条件(GIVEN)**: 已登录
- **操作(WHEN)**: 声明 int 的字段送字符串 `"abc"`
- **预期结果(THEN)**: 400，类型错误提示；无副作用
- **优先级**: P0
- **测试方法**: 错误推测

#### TC-103: 空字符串
- **前置条件(GIVEN)**: 已登录
- **操作(WHEN)**: 字符串字段送 `""`
- **预期结果(THEN)**: 400 或按规则处理（与契约一致）
- **优先级**: P1
- **测试方法**: 边界（特殊值）

#### TC-104: null 值
- **前置条件(GIVEN)**: 已登录
- **操作(WHEN)**: 必填字段送 `null`
- **预期结果(THEN)**: 400，不允许为 null
- **优先级**: P1
- **测试方法**: 错误推测

#### TC-105: 超长字符串
- **前置条件(GIVEN)**: 已登录；字段定义 max_length=N
- **操作(WHEN)**: 长度 = N + 1
- **预期结果(THEN)**: 400，长度超限
- **优先级**: P1
- **测试方法**: 边界（离点）

#### TC-106: 特殊字符
- **前置条件(GIVEN)**: 已登录
- **操作(WHEN)**: 含中文 / emoji / SQL 关键字字面量
- **预期结果(THEN)**: 200（正常入库）或 400（按白名单拒绝）
- **优先级**: P2
- **测试方法**: 错误推测

#### TC-107: 枚举非法值
- **前置条件(GIVEN)**: 已登录
- **操作(WHEN)**: enum 字段送约定外的值
- **预期结果(THEN)**: 400，非法枚举值
- **优先级**: P1
- **测试方法**: 等价类（无效类）

### 避免冗余

- 边界值（min/max ± 1 的数值）属维度 3，本维度只覆盖明显非法输入

## 维度 3：边界场景

- **ID 前缀**：TC-2xx
- **何时适用**：参数有数值上下限或长度上下限时
- **设计思路**：边界值分析（上点 / 内点 / 离点）

### 典型用例骨架

#### TC-201: 数值下边界内点
- **前置条件(GIVEN)**: 已登录；字段 min=N
- **操作(WHEN)**: 值 = N
- **预期结果(THEN)**: 200，正常处理
- **优先级**: P0
- **测试方法**: 边界（上点）

#### TC-202: 数值下边界离点
- **前置条件(GIVEN)**: 已登录；字段 min=N
- **操作(WHEN)**: 值 = N - 1
- **预期结果(THEN)**: 400，越界
- **优先级**: P0
- **测试方法**: 边界（离点）

#### TC-203: 数值上边界内点
- **前置条件(GIVEN)**: 已登录；字段 max=M
- **操作(WHEN)**: 值 = M
- **预期结果(THEN)**: 200，正常处理
- **优先级**: P0
- **测试方法**: 边界（上点）

#### TC-204: 数值上边界离点
- **前置条件(GIVEN)**: 已登录；字段 max=M
- **操作(WHEN)**: 值 = M + 1
- **预期结果(THEN)**: 400，越界
- **优先级**: P0
- **测试方法**: 边界（离点）

#### TC-205: 长度上边界内点
- **前置条件(GIVEN)**: 已登录；字符串字段 max_length=L
- **操作(WHEN)**: 长度 = L
- **预期结果(THEN)**: 200
- **优先级**: P1
- **测试方法**: 边界（上点）

### 避免冗余

- 参数类型错属维度 2（如送字符串到数值字段）
- 空值 / null 属维度 2
- 仅当字段定义有 min/max 或 min_length/max_length 时才生成此维度用例
- 分页参数（page/pageSize）边界默认跳过（详见维度 5「分页参数用例默认跳过」）

## 维度 4：业务规则

- **ID 前缀**：TC-3xx
- **何时适用**：始终（specs 存在时 spec 驱动，不存在时通用推断兜底；至少有"资源不存在"等通用业务规则可生成）
- **设计思路**：**spec scenario 驱动优先** + 状态转换 + 决策表
- **数据来源**：specs/*.md scenario（主） + design.md 状态机（辅） + 通用推断（兜底）

### Spec Scenario 驱动（优先级最高）

当 `specs/*.md` 中存在与当前接口相关的 Scenario 时，**每个相关 Scenario 对应生成 1 条 TC-3xx**：

**映射规则**：
1. Scenario 的 GIVEN → TC 的前置条件(GIVEN)
2. Scenario 的 WHEN → TC 的操作(WHEN)，关联到具体接口的 method + path + body
3. Scenario 的 THEN → TC 的预期结果(THEN)
4. TC 标题格式：`### TC-3xx: <scenario_name> - 业务规则(spec)`

**示例**：

```markdown
# spec 原文
#### Scenario: 超出任务上限时创建失败
- **WHEN** 用户已有 3 个 status=processing 的任务，尝试创建新任务
- **THEN** 返回错误，提示任务数已达上限

# → 生成的 TC
### TC-301: 超出任务上限时创建失败 - 业务规则(spec)
- **前置条件(GIVEN)**:
  - 已登录(同公共约定)
  - 用户已有 3 个 status=processing 的任务
- **操作(WHEN)**:
  - POST /task/create
  - Body: {"name":"new_task",...}
- **预期结果(THEN)**:
  - HTTP 200
  - status_code != 1
  - msg 含 "上限" 或 "exceed"
```

**生成顺序**：spec 驱动的 TC-3xx 在前 → design 状态机驱动 → 通用推断在后。

### Design 状态机驱动（辅助）

当 `design.md` 定义了状态机时，自动生成：
- 每条合法转换的正向用例（可合并为 TC-5xx 全链路）
- 每条**非法转换**的 TC-3xx（从非相邻状态直接跳转）
- 终态不可逆用例

### 通用推断骨架（兜底）

specs/ 不存在时，退回以下通用推断模式。以下为通用推断的典型 TC 骨架：

#### TC-301: 状态转换非法 - 已删除资源再次删除
- **前置条件(GIVEN)**: 已登录；资源 id=X 状态=deleted
- **操作(WHEN)**: 对资源 X 再次执行删除
- **预期结果(THEN)**: 409 或 404，不可重复操作；DB 无变化
- **优先级**: P0
- **测试方法**: 状态转换

#### TC-302: 终态不可逆 - 已支付订单再次支付
- **前置条件(GIVEN)**: 已登录；订单 id=Y 状态=paid
- **操作(WHEN)**: 对订单 Y 触发 pay 事件
- **预期结果(THEN)**: 409，订单状态不允许；订单状态保持 paid
- **优先级**: P0
- **测试方法**: 状态转换

#### TC-303: 前置依赖缺失
- **前置条件(GIVEN)**: 已登录；不存在父记录
- **操作(WHEN)**: 创建子记录（如未建订单先付款）
- **预期结果(THEN)**: 400 / 404，前置不存在
- **优先级**: P1
- **测试方法**: 决策表

#### TC-304: 幂等性 - 重复提交
- **前置条件(GIVEN)**: 已登录；存在 idempotency_key=K
- **操作(WHEN)**: 用相同 K 提交两次相同请求
- **预期结果(THEN)**: 第二次返回与第一次相同结果；DB 无重复副作用
- **优先级**: P0
- **测试方法**: 错误推测

#### TC-305: 跨状态非法跳转
- **前置条件(GIVEN)**: 已登录；资源状态=draft，状态机要求 draft → published → archived
- **操作(WHEN)**: 触发 draft → archived
- **预期结果(THEN)**: 409，状态机非法转换
- **优先级**: P1
- **测试方法**: 状态转换

#### TC-306: 并发竞争 / 消息重试安全
- **前置条件(GIVEN)**: 已登录；资源 id=X 状态允许操作
- **操作(WHEN)**: 两个请求同时修改同一资源（不同 payload 或不同调用方）
- **预期结果(THEN)**: 仅一个成功 + 另一个返回冲突/幂等；资源无脏写
- **优先级**: P1
- **测试方法**: 并发竞争

### 决策表识别信号与生成规则

**识别信号**（命中任一即生成决策表式 TC-3xx）：

| 信号 | 典型表现 | 示例 |
|---|---|---|
| 字段条件依赖 | 字段 A 的取值决定字段 B 必填/可选/禁填 | `is_custom_welcome=1` 时 `message` 必填，`=0` 时 `message` 须为空 |
| 枚举→字段集映射 | 枚举字段不同取值对应不同可填字段组 | `type=text` 允许 `content`，`type=image` 允许 `media_id` |
| 互斥条件组 | 多个字段不能同时非空/同时为空 | `start_time` 与 `cron_expr` 二选一 |
| 组合边界 | 两个字段组合值域有联合约束 | `min_amount ≤ max_amount` |

**生成规则**：

1. 条件组合 ≤ 6 行 → 1 条 TC（WHEN 段用变体表列出所有组合）
2. 条件组合 > 6 行 → 拆为"合法组合"1 条 + "非法组合"1 条（各含数据驱动表）
3. 决策表 TC 标题格式：`### TC-3xx: <字段A> × <字段B> 决策表 - 业务规则`
4. WHEN 变体表格式：

```markdown
- **操作(WHEN)**:
  - 对下列每组 Body 各发送一次（决策表）：
    | is_custom | message | 预期 |
    |---|---|---|
    | 1 | "hello" | ✅ 成功 |
    | 1 | "" | ❌ message 必填 |
    | 0 | "hello" | ❌ message 须为空 |
    | 0 | "" | ✅ 成功 |
```

**与数据驱动合并的区别**：
- 数据驱动：同一字段多个无效值，THEN 相同 → 纯变体表
- 决策表：多字段组合，每种组合 THEN 不同 → 含"预期"列的矩阵表

> 注：数据驱动变体表和决策表矩阵属于 WHEN 段内的**参数化描述**，不受"全文无横排用例表格"规则约束。该规则禁止的是把整条用例（GIVEN+WHEN+THEN）写成一行表格行。

### 并发与重试安全（内部接口补充）

**判断信号**（命中任一则生成 TC-306 并发/重试用例）：

| 信号 | 来源 | 说明 |
|---|---|---|
| 写操作 + 状态变更 | yapi.md 中 POST/PUT/PATCH + 响应含 status 字段 | 并发修改可能脏写 |
| design.md 提到队列/worker/异步 | 设计文档含 queue / consumer / retry / worker | 消息可能重复投递 |
| 接口含 version / updated_at 乐观锁字段 | body_schema 含 version / etag | 并发冲突检测 |
| spec scenario 提到"同时" / "并发" | specs WHEN 含并发语义词 | 显式并发需求 |

**与 TC-304 幂等性的区别**：
- TC-304 幂等：同一调用方、相同 idempotency_key、连续发两次 → 不重复执行
- TC-306 并发：不同调用方（或队列重试）、不同/相同 payload、同一时刻竞争同一资源 → 不脏写

**不生成的场景**：纯查询接口（GET）、无状态变更的接口、已有 `@Transactional` / 事务标记的接口（由框架保证）。

### 避免冗余

- 参数格式错属维度 2
- 仅当接口涉及资源状态、依赖、幂等语义时才生成

### 内部接口默认跳过的用例

为**公司内部接口**生成用例时，下列四类 TC-3xx 默认**不生成**（除非用户明确要求测安全边界）：

| 默认跳过类别 | 理由 |
|---|---|
| 未登录 / 鉴权失败（401） | 鉴权由全局中间件统一处理，不在单接口用例反复验证 |
| csrf token 不匹配（403） | 同上，约定俗成的全局校验 |
| 跨主体 / 跨企业数据隔离（返回空集校验） | 多租户隔离是基础设施层面的全局保证 |
| 非管理员账号访问管理接口 | RBAC 由全局中间件统一处理 |

**判断「内部接口」的信号**:

**默认按内部接口处理**,跳过鉴权/csrf/数据隔离/非管理员四类 TC-3xx。

**反向白名单(命中则按对外接口处理,生成完整鉴权类 TC)**:
- 路径前缀 `/openapi/` / `/public/` / `/v1/` / `/v2/` / `/v3/` / `/api/v[0-9]+/`
- 用户显式说明「这是对外接口 / 公开 API / SDK 接口」
- 输入文档明确标注 "公开" / "external" / "third-party"

**强化的内部信号**(命中任一,即使路径符合白名单也按内部处理):
- 输入文档来源为 yapi(`doc.wozhangwan.com` 等内部 URL)
- 路径含 `/admin/` / `/sidebar/` / `/internal/` / `/internal-api/` 前缀
- 用户显式说明「内部系统 / 公司内部」
- **input 来自 openspec/changes/<change_name>/yapi.md** — openspec 工作流通常是公司内部变更管理,即便接口路径在公开白名单(如 `/v1/`),整体仍按内部处理

> 优先级:**强化内部信号 > 反向白名单 > 默认内部**

**仍要保留的 TC-3xx**：与**当前接口业务语义**强相关的规则用例
- 资源不存在（如 `userid 不存在`、`open_kfid 不存在`）
- 资源已被软删除
- 同项目下名称重名冲突
- 外键依赖不存在（如 `weixin_blongs_id 不存在`）
- 状态机非法转换、幂等性、终态不可逆
- 字段决策表（如 `is_custom_welcome=1` 时 `message` 必填，=2 时须为空）

不要反问用户「需不需要测鉴权」，按以上默认行事；用户主动提"测一下安全边界 / 越权访问"再加。

## 维度 5：响应校验

- **ID 前缀**：TC-4xx
- **何时适用**：始终
- **设计思路**：等价类（合法响应字段集）+ 场景法

### 典型用例骨架

#### TC-401: 字段完整性
- **前置条件(GIVEN)**: 已登录；合法主链路输入
- **操作(WHEN)**: 发送 TC-001 的同款请求
- **预期结果(THEN)**: 响应必含契约声明的全部必返字段，无缺失
- **优先级**: P0
- **测试方法**: 等价类（响应有效类）

#### TC-402: 字段类型匹配
- **前置条件(GIVEN)**: 已登录；合法请求
- **操作(WHEN)**: 同 TC-401
- **预期结果(THEN)**: 字段类型与契约一致（如声明 int 不返回 "123" 字符串）
- **优先级**: P0
- **测试方法**: 契约校验

#### TC-403: 排序约定
- **适用条件**: 仅当响应字段含 `created_at` / `updated_at` / `id` / `sort_order` 等有自然顺序字段时生成
- **前置条件(GIVEN)**: 已登录;列表查询场景
- **操作(WHEN)**: 不传排序字段
- **预期结果(THEN)**: 默认按 `created_at desc`(或契约约定字段)
- **优先级**: P1
- **测试方法**: 场景法

#### TC-404: 空结果集结构
- **前置条件(GIVEN)**: 已登录；查询条件无匹配数据
- **操作(WHEN)**: 合法但无结果的查询
- **预期结果(THEN)**: list=[]，total=0；不返回 null
- **优先级**: P1
- **测试方法**: 错误推测（空集场景）

#### TC-405: 敏感字段脱敏
- **适用条件**: 仅当响应字段名含 `phone` / `mobile` / `id_card` / `password` / `email` / `bank_account` / `secret` / `api_key` 等敏感字段时生成
- **前置条件(GIVEN)**: 已登录;响应含手机号 / 身份证 / 密码字段
- **操作(WHEN)**: 合法请求
- **预期结果(THEN)**: 按契约规则脱敏或不返回
- **优先级**: P1
- **测试方法**: 场景法

### 避免冗余

- 错误响应（4xx / 5xx 的结构）已分布在维度 2 / 4 内，本维度只验"成功响应"
- 不要重复维度 1 的请求场景，本维度聚焦响应侧断言

### 分页参数用例默认跳过

下列**分页参数本身**的用例**默认全部不生成**(除非用户明确要求测分页):

| 跳过类别 | 涵盖参数 | 跨维度位置 |
|---|---|---|
| 分页参数必填缺失 | `page` / `pageSize` / `page_size` / `count` / `pageNo` / `limit` / `offset` | 原 TC-1xx |
| 分页参数类型错配 | 同上字段送字符串/null/小数 | 原 TC-1xx |
| 分页参数边界离点 | `page=0` / `pageSize=0` / `pageSize=超上限` | 原 TC-2xx |
| 分页参数远超总页 | `page=99999` 远超总页数返回空集 | 原 TC-2xx 或 TC-3xx |
| 分页字段一致性 | total / page / pageSize 三者自洽 | 原 TC-404 |

**理由**: 分页是 list 接口的**通用约定**,由前端 SDK / 网关层 / 框架统一保证,不在单接口用例范围内反复验证。

**仍要保留的列表相关 TC**:
- 业务筛选字段的过滤效果(`channel` / `external_userid` / 日期区间 等业务参数)
- 查询无结果的空集**结构**契约(响应字段类型,如 `list=[]` 而非 `null`),但不再断言 `total=0/page=1/pageSize=20` 三者关系
- 列表项内部字段的契约校验

**判断信号**: 用例 GIVEN/WHEN 内出现 `page` / `pageSize` / `page_size` / `count` / `pageNo` 等参数名作为**校验主体**时跳过;**仅作为请求基线 Body 携带**(不参与断言)时保留。

**例外**: 用户主动说"测一下分页边界" / "page=0 必须报错" → 才生成对应用例。

## 维度 6：集成场景

- **ID 前缀**：TC-5xx
- **何时适用**：yapi.md 有 ≥2 个接口，且满足以下之一：
  - prd.md 描述了跨接口业务流程
  - spec scenario 的 WHEN 涉及多个接口动作（"创建后查询"等）
  - design.md 定义了状态机（状态流转必然跨多次调用）
- **设计思路**：端到端流程法 + 场景法
- **数据来源**：prd.md 业务流程 + spec scenario 多步骤场景 + design.md 状态机

### 适用条件（全部满足才生成）

1. yapi.md 中有 ≥ 2 个接口
2. 至少有一个跨接口信号来源（prd 流程 / 多步骤 scenario / 状态机）

**不生成 TC-5xx 的情况**：
- 单接口 change
- specs/ 和 prd.md 均不存在
- 所有 scenario 都只涉及单个接口

### 典型用例骨架

#### TC-501: 完整业务流程 - 正向主链路

- **前置条件(GIVEN)**:
  - 已登录
  - 依赖数据已就绪（如模板存在、余额充足）
- **操作(WHEN)**:
  - Step 1: POST /task/create → response.data.id 记为 `$task_id`
  - Step 2: POST /task/submit {"task_id": "$task_id"}
  - Step 3: GET /task/status?task_id=$task_id（轮询至终态）
- **预期结果(THEN)**:
  - Step 1: status_code=1，返回 task_id
  - Step 2: status_code=1，task 状态变为 processing
  - Step 3: status=completed，结果字段非空

#### TC-502: 状态机全链路 - 从初态到终态

- **前置条件(GIVEN)**:
  - 资源处于初始状态（如 draft）
- **操作(WHEN)**:
  - 按 design.md 定义的状态机路径依次调用转换接口：
  - Step 1: draft → published（POST /xxx/publish）
  - Step 2: published → archived（POST /xxx/archive）
- **预期结果(THEN)**:
  - 每步状态字段正确反映转换
  - 到达终态后查询确认

#### TC-503: 流程中断后数据一致性

- **前置条件(GIVEN)**:
  - 流程已执行到中间步骤（如已创建但未提交）
- **操作(WHEN)**:
  - 中间步骤因业务规则失败（如余额不足）
- **预期结果(THEN)**:
  - 已执行步骤的数据完整（不回滚已创建的资源）
  - 查询接口返回的状态反映中间态
  - 修复条件后可重试

### 生成规则

- **上限 5 条**：集成用例执行成本高，聚焦关键路径
- **编号独立**：TC-5xx 在文档级独立编号（不属于任何模块），放在所有模块之后
- **Step 引用校验**：每个 Step 的接口路径必须存在于 yapi.md 中
- **来源标注**：TC 标题含来源标记 `(prd)` / `(spec)` / `(状态机)`

### 避免冗余

- 单接口的正常/异常场景属维度 1-4，不重复放 TC-5xx
- TC-5xx 聚焦"接口之间的数据流转和状态联动"
- 不测试每个步骤的参数校验（那属于各模块的 TC-1xx）
- 如果 spec scenario 只涉及单个接口，归 TC-3xx 而非 TC-5xx

### 不存在时跳过

specs/ 和 prd.md 均不存在，或单接口 change → TC-5xx 整个维度跳过，不生成空章节。
